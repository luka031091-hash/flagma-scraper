# Flagma Scraper

Apify-актор для збору оголошень з [Flagma.ua](https://flagma.ua) у структурований датасет. Працює на **Crawlee CheerioCrawler** (HTTP, без браузера) — швидко й економно.

**Лише збір даних** — без арбітражної логіки. Зіставлення «куплю ↔ продам» і розрахунок маржі — окремий інструмент.

---

## Що збирає

За заданими URL сторінок пошуку або категорій Flagma актор проходить пагінацію, відкриває кожне оголошення й збирає: назву, опис, категорію, ціну (число + валюта + одиниця + оригінальний текст), тип (куплю/продам), продавця, локацію, **телефон**, фото, дату. Результат експортується в **CSV / JSON / Excel**.

## Можливості

- ⚡ HTTP-краул (CheerioCrawler) — у рази швидше за браузерні скрейпери
- 📞 Телефон зі статичного HTML (без логіну й капчі)
- 🧩 Парсинг через **JSON-LD** (Schema.org) + CSS-fallback — стійко до зміни розмітки
- 🔁 Автоматична пагінація + дедуплікація за `id`
- 🛡️ Контроль темпу (rate limit) + підтримка проксі проти бана
- ✅ 33 юніт-тести на реальних HTML-фікстурах

## Швидкий старт (локально)

```bash
git clone https://github.com/luka031091-hash/flagma-scraper.git
cd flagma-scraper
npm install
apify run
```

Вхідні дані для локального запуску беруться з `storage/key_value_stores/default/INPUT.json`. Щоб задати свій запит — відредагуй `input.json` і запусти:

```bash
apify run -i input.json
```

Зібрані дані з'являться в `storage/datasets/default/` (по одному JSON-файлу на оголошення).

## Вхідні параметри

| Параметр | Тип | Дефолт | Опис |
|---|---|---|---|
| `startUrls` | масив | — *(обов'язково)* | Сторінки пошуку/категорій Flagma |
| `listingType` | рядок | `all` | Тип оголошень: `all` — всі, `buy` — лише «Куплю» (попит), `sell` — лише «Продам» |
| `maxItems` | число | `0` | Ліміт оголошень за запуск (`0` = без ліміту) |
| `maxRequestsPerMinute` | число | `40` | Темп запитів (анти-бан) |
| `maxConcurrency` | число | `3` | Кількість одночасних запитів |
| `maxRequestRetries` | число | `5` | Повтори заблокованого (403) запиту з ротацією сесії |
| `fetchPhones` | булеве | `true` | Чи збирати телефони продавців |
| `proxyConfiguration` | об'єкт | без проксі | Налаштування проксі (див. нижче) |

Приклад вхідних даних (зібрати лише оголошення «Куплю»):

```json
{
  "startUrls": [{ "url": "https://flagma.ua/uk/products/q=куплю/" }],
  "listingType": "buy",
  "maxItems": 100,
  "fetchPhones": true
}
```

> 🔎 **Фільтр `listingType`.** Тип визначається з бейджа «Куплю» на картці списку і застосовується **до** завантаження detail-сторінок — у чергу потрапляють лише потрібні картки. Це менше запитів і менший ризик 403-банів. Пагінація проходить усі сторінки незалежно від фільтра.

> ⚠️ **Проксі.** Flagma блокує datacenter-проксі (Apify Proxy за замовчуванням — саме datacenter), тоді збір повертає **0 лотів**. Тому дефолт — **без проксі** (прямі запити). Для великих обсягів вмикайте **RESIDENTIAL**-проксі.

## Структура результату

Кожне оголошення — один запис із такими полями:

| Поле | Опис |
|---|---|
| `id` | унікальний id оголошення (числовий суфікс URL) |
| `url` | посилання на оголошення |
| `sourceStartUrl` | з якої стартової сторінки прийшов лот |
| `listingType` | `куплю` / `продам` / `null` (евристика) |
| `title` | назва |
| `description` | повний опис |
| `rawPrice` | оригінальний текст ціни (вкл. «договірна») |
| `normalizedPrice` | ціна числом, або `null` для нечислових |
| `currency` | валюта (UAH/USD/EUR/…) |
| `priceUnit` | одиниця (штука/кг/тонна/…) |
| `category` | категорія |
| `seller` | `{ name, type }` — продавець і тип (ФОП/ТОВ/приватна) |
| `location` | `{ city, region, country }` |
| `phone` | телефон продавця (або `null`) |
| `phoneStatus` | `found` / `hidden` / `failed` / `disabled` |
| `images` | масив URL фото |
| `publishedAt` | дата публікації/оновлення оголошення |
| `scrapedAt` | час збору (ISO-8601) |

## Структура проєкту

```
flagma-scraper/
├── src/
│   ├── main.js        # вхід: читає Input, конфігурує краулер, запускає
│   ├── routes.js      # хендлери LIST/DETAIL + чисті парс-функції
│   ├── phone.js       # збір телефону (єдине місце знань про блок контактів)
│   ├── selectors.js   # УСІ CSS-селектори в одному місці
│   └── normalize.js   # нормалізація ціни/типу/продавця/локації + JSON-LD
├── test/              # 33 юніт-тести + збережені HTML-фікстури
├── scripts/           # GATE №0 — прототип перевірки телефону
└── .actor/            # actor.json + input/output/dataset схеми
```

Архітектура: двофазний краул через роутер — `LIST` (картки → черга `DETAIL` + наступна сторінка) і `DETAIL` (усі поля + телефон → запис у dataset).

## Обмеження (чесно)

- **Тип оголошення** (`listingType`) часто `null` — евристика визначає його лише за явною міткою на сторінці або словом у URL.
- **Одиниці ціни не зведені до спільної бази** (тонна/кг/штука) — для прямого порівняння цін потрібна конвертація.
- **Ціна `0`** зазвичай означає «без ціни / договірна» — дивись `rawPrice`.
- Зберігається **перший** телефон, якщо продавець вказав кілька.

## Юридично-етичне зауваження

Масовий збір телефонів — це збір контактних/персональних даних і може суперечити ToS Flagma та нормам захисту даних. Свідомі запобіжники: помірний темп запитів; використання **приватно** для власної аналітики; **не публікувати й не перепродавати** зібрані контакти. Збір телефонів можна вимкнути (`fetchPhones: false`).
